# Execution image decision and license review (#43)

Reviewed 2026-11-05. Maintainer-level analysis, not legal advice or a formal ADR.
ADRs remain Proposed until accepted by the maintainers' process.

## Execution image: not needed for the offline alpha; deferred for execution

Decision for `v0.1.0-alpha.0`: **no image**. The alpha is the credential-free offline
CLI; an image of the Control Plane, Worker or Runner would imply a runnable,
supported execution course that does not exist (the Compose template is an unverified
developer assembly and the ECS path has no live validation). #43's image condition
stays open, not satisfied.

When to build: after the dedicated-staging gate in
[ecs-staging-acceptance.md](ecs-staging-acceptance.md) has real evidence. Then:

- Separate images for `cmd/themisy` (control/worker) and `cmd/runner`; the Runner image
  holds the credential boundary, so it is minimal (static Go binary, distroless
  nonroot, read-only root filesystem, no shell) and receives secrets only via
  customer-mounted files.
- Pin base images by digest; build in CI from a committed ref; attach the same
  Sigstore provenance and an SPDX SBOM as the CLI workflow
  (`offline-release-candidate.yml` is the pattern); publish by digest, never `latest`.
- Ship `THIRD_PARTY_NOTICES.txt` (see below) and run the Go vulnerability scan on the
  exact build.
- Do not ship example secrets, trust material or the Compose bind-mount layout.

## License review (linked Go modules)

Reproduce: `python3 scripts/license_inventory.py ./cmd/themisyctl` (CLI) or `./cmd/...`.

| Scope | Result 2026-11-05 |
|---|---|
| CLI (`./cmd/themisyctl`), 35 modules | Apache-2.0 16, MIT 13, BSD-3-Clause 5, BSD-2-Clause 1; none needs review |
| All commands (`./cmd/...`), 69 modules | Apache-2.0 29, MIT 26, BSD-3-Clause 10, BSD-2-Clause 2, ISC 1; one module with no license file in the module cache: `nexus-rpc/nexus-proto-annotations@v0.1.0` — its upstream repository declares MIT (GitHub license API) but that is not confirmed in the cached module, so it must be re-verified before any image. **Re-verified 2026-11-07 against upstream:** tag `v0.1.0` (commit date 2026-03-30) contains no LICENSE file (tree: README.md, buf files, go.mod/go.sum, `go/`, `nexusannotations/`); the MIT LICENSE was added on the default branch on 2026-06-29, after the tag. The declared MIT therefore does not apply to the pinned `v0.1.0` content as published. Before building any execution image: upgrade to a tagged release that ships the LICENSE, or obtain written confirmation from upstream, or exclude the module; do not ship it under an assumed MIT notice |
| Copyleft (GPL/AGPL/MPL) | None detected by the heuristic |

Classification is a text heuristic; unknown texts are reported, not guessed. The SBOM
keeps `NOASSERTION` for licenses.

### Finding fixed: missing third-party notices

`v0.1.0-alpha.0` bundles Themisy's own `LICENSE` but **not** the Apache/MIT/BSD
notices of linked modules and the Go standard library, which these licenses ask
redistributors of binaries to reproduce. Candidates built from this change include
`THIRD_PARTY_NOTICES.txt` (generated by `scripts/third_party_notices.py`; it fails if
any linked module lacks a license file) and the verifier requires it. The already
published `v0.1.0-alpha.0` archive lacks it; the next candidate (`0.1.0-alpha.1`)
should be released and the earlier prerelease annotated as superseded — a maintainer
decision, not done here.
