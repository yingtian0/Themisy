# Maintainers and contacts

This file states the current state; it promises no response time (SLA).

## Active maintainer

| Person | Scope | Availability |
|---|---|---|
| [@yingtian0](https://github.com/yingtian0) | Triage, review, releases, roadmap, security response, Code of Conduct | One active maintainer; part-time, best effort |

There is currently **one** active maintainer. Reviews that [GOVERNANCE.md](GOVERNANCE.md)
asks two maintainers to approve cannot be double-approved until a second
maintainer is appointed; changes will say so rather than imply a second review.
A reviewer may be appointed in a public governance issue under GOVERNANCE.md
after sustained, reviewed contributions in a defined area. No one else is
appointed today.

## Where to go

| Purpose | Entry | Notes |
|---|---|---|
| Question about a non-sensitive change, design discussion | The relevant Issue, or [#45](https://github.com/yingtian0/Themisy/issues/45) for first contributions | Public |
| Bug report | [Bug report form](https://github.com/yingtian0/Themisy/issues/new/choose) | Minimal reproduction, no secrets or customer data |
| Suspected vulnerability | GitHub **Security → Report a vulnerability** (private) per [SECURITY.md](SECURITY.md) | Never in a public Issue/PR |
| Code of Conduct concern | Email haidouyingtian0@gmail.com | Private; not for vulnerabilities |

If the private vulnerability form is unavailable, open a public Issue containing no
details asking for a channel, as SECURITY.md describes. Do not send exploit
details, credentials or customer data by email.

## Triage and absence

- The maintainer triages new Issues and PRs on a best-effort basis. Security
  reports are handled first; targets are in SECURITY.md and are not guarantees.
- During absence, responses may be delayed. There is no deputy yet; this is a
  known limitation, not a covered service.
