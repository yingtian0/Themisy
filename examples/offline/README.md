# Offline planning example fields

Run from the repository root with Go 1.26.10 or later:

```bash
go run ./cmd/themisyctl offline-plan -at 2026-10-18T00:00:00Z examples/offline/release.json
```

This reads the local Service Contracts and Release Profiles and produces a
synthetic plan. Values below describe the checked-in example; they are not
verified identity, CI, runtime health, approval, or permission to execute.
The command creates no Grant, obtains no credentials, and performs no writes.

## Intent to plan

| Intent field | Example value | Where it appears or what it controls |
|---|---|---|
| `api_version`, `kind` | `execution.themisy.io/v1alpha1`, `ReleaseIntent` | Selects the versioned input format. |
| `request_id` | `offline-demo-001` | Identifies this synthetic request. |
| `release_version` | `offline-demo` | Appears on the resulting Plan. |
| `tenant_id` | `synthetic-local` | Synthetic tenant; copied into scheduling context. |
| `environment` | `staging` | Selects the `staging` Contract environment. |
| `requested_by` | `synthetic-user` | Synthetic requester; not authenticated. |
| `changes[].service` | `identity-api` | Selects `examples/contracts/identity-api.yaml`. |
| `changes[].desired_version` | `sha-demo` | Planned target shown on the Step. It is not checked against a registry or image digest. |

The selected Contract supplies owner (`identity-team`), risk tier (`high`),
Runner Group (`staging-ap-northeast-1`), and allowed capabilities. The
`staging` environment selects `ecs-rolling-standard`. That Profile requires
`deploy`, `get_status`, `verify_runtime`, and `rollback`, requires verification
with a five-minute observation window, and uses automatic rollback. These are
local configuration declarations, not proof those systems or credentials are
available.

## Plan output

| Output field | Meaning in this example |
|---|---|
| `plan.phases[0].steps[0].service` | `identity-api`, the changed Contract. |
| `desired_version` | `sha-demo`, copied from the Intent. |
| `profile` | `ecs-rolling-standard`, selected by the Contract environment. |
| `required_capabilities` | The sorted capabilities required by the selected Profile. |
| `scheduling.runner_group` | `staging-ap-northeast-1`, from the Contract's staging environment. |
| `scheduling.team`, `risk_tier` | `identity-team` and `high`, from the Contract metadata. |
| `contract_hash`, `profile_hash` | Canonical hashes computed from the loaded Contract/Profile. Do not hand-author these. |
| `change_hash` | Hash of the planned change, including its selected inputs. |
| `hash`, `plan_hash` | Identical canonical hash for this complete Plan. |
| `context_snapshot_ref` | Reference to the locally computed synthetic planning context. |
| `created_at`, `expires_at` | Fixed by `-at`; this example expires 15 minutes after that time. Expiry does not grant or extend execution authority. |

Hashes are generated by the same deterministic planner used by the service.
They are comparison values, not signatures or proof of external verification.
The displayed synthetic `sha-demo` is not an image digest validation result.

For a rejected input, run:

```bash
go run ./cmd/themisyctl offline-plan examples/offline/rejected.json
```

It exits with code 1 because `missing-api` has no corresponding Contract. No
Plan is emitted. See [the 15-minute course](../../docs/guides/offline-quickstart.md)
for setup, expected output, and the limits of this exercise.
